# Настройка распознавания через сайт Cloudflare

Для APK **0.5.0**. Распознавание выполняется только в Cloudflare Workers AI. В APK нет локального движка и словарей. Установка — через браузер, без командной строки, Wrangler и API-токенов.

Нужны ваш аккаунт Cloudflare, Worker и бесплатная база D1 для счётчика запросов. Фото и текст в D1 не сохраняются. Если Worker ещё не создан, пройдите шаги ниже. Из среды разработки ничего в ваш аккаунт не публикуется.

## 1. Обновить приложение и получить ROOMS

1. [Скачайте APK 0.5.0](https://github.com/firesemen/goods_page/raw/refs/heads/fridge-days/downloads/fridge-days-0.5.0-debug.apk). Установите её **поверх текущей версии**, без удаления приложения, на оба телефона.
2. Откройте **шестерёнку → Распознавание по фото → Параметры ROOMS для распознавания → Копировать**.
3. Сохраните всю скопированную строку для шага 4. Она выглядит так:

```json
{"UUID_СЕМЬИ_UUID_ХОЛОДИЛЬНИКА":"64_шестнадцатеричных_символа"}
```

Пример не рабочий: используйте значение именно со своего телефона. Копируйте JSON целиком, с фигурными скобками и кавычками. Если телефоны уже в одной семье, значение у них общее. Кнопка регистрации **ретранслятора** в разделе «Семья» выдаёт другое разрешение — его сюда вставлять нельзя.

В `ROOMS` находится хеш отдельного разрешения распознавания. Пароль Cloudflare, приглашение с ключом семьи и ключ расшифровки продуктов в Worker вставлять не нужно.

## 2. Создать D1

1. Откройте [dash.cloudflare.com](https://dash.cloudflare.com/) и выберите аккаунт.
2. В меню аккаунта найдите **Storage & databases → D1 SQL Database** (или просто **D1**).
3. Нажмите **Create database**, задайте название `fridge-photo-usage` и создайте базу.
4. В созданной базе откройте **Console**, вставьте SQL ниже и нажмите **Execute / Run**:

```sql
CREATE TABLE IF NOT EXISTS recognition_usage (
  room TEXT NOT NULL,
  day TEXT NOT NULL,
  count INTEGER NOT NULL,
  PRIMARY KEY(room,day)
);
```

Это [schema.sql](schema.sql). Пустая таблица после выполнения — ожидаемый результат.

## 3. Создать Worker и вставить код

1. Откройте **Workers & Pages → Create application → Create Worker**. В новом меню раздел может находиться в **Compute & AI**.
2. Выберите **Start with Hello World**, задайте свободное имя, например `fridge-photo-yourname`, и нажмите **Deploy**.
3. Откройте созданный Worker → **Edit code**.
4. Откройте [готовый worker.js](worker.js), нажмите **Raw** и скопируйте весь файл.
5. Полностью замените содержимое основного `worker.js` в редакторе Cloudflare. Нужен весь файл, включая `export default`; дополнительные файлы и npm-пакеты не требуются.
6. Нажмите **Deploy**.

Если Worker был создан ранее, замените его код этим файлом и сохраните существующие привязки. Новая версия добавляет проверку подключения; путь распознавания и формат `ROOMS` прежние.

## 4. Подключить AI, базу и ROOMS

На странице Worker откройте **Bindings** либо **Settings → Bindings → Add**:

| Тип | Variable name | Значение |
|---|---|---|
| Workers AI | `AI` | Подключить Workers AI своего аккаунта |
| D1 database | `DB` | Выбрать `fridge-photo-usage` |

Регистр важен: `AI` и `DB`. Если Cloudflare предложит принять условия Workers AI, ознакомьтесь с ними перед подключением.

Затем **Settings → Variables and Secrets → Add**:

| Имя | Тип | Значение |
|---|---|---|
| `ROOMS` | Secret | Весь JSON, скопированный из приложения на шаге 1 |
| `DAILY_LIMIT` | Text | `20` |

Сохраните изменения через **Save / Deploy**, если панель предлагает их применить. `ROOMS` — один секрет со всей строкой JSON. Свой API-токен Cloudflare в код и приложение добавлять не нужно: модель `@cf/google/gemma-3-12b-it` вызывается через привязку `AI`.

Если `gemma-3-12b-it` отсутствует в вашем каталоге, задайте дополнительную Text-переменную `VISION_MODEL` = `@cf/google/gemma-4-26b-a4b-it` (модель с Vision). Это меняет выбор модели без обновления APK; совместимость обработки изображения и фактический ответ нужно проверить шагом 6.

Лимит — 20 попыток на семью/холодильник за сутки UTC, включая ошибки после обращения к модели. Разрешено от 1 до 100; для первого теста можно поставить `5`. Проверка подключения не расходует этот счётчик и не вызывает модель.

У Workers AI есть бесплатная квота в Neurons, а у Workers и D1 — свои лимиты. Счётчик попыток не равен финансовому лимиту: расход зависит от снимков и модели. Для бесплатного пилота используйте **Workers Free**, проверьте [текущую тарификацию](https://developers.cloudflare.com/workers-ai/platform/pricing/) и не подключайте платный план ради работы приложения. Если аккаунт уже платный, проверьте его условия оплаты. Если панель требует оплату, остановитесь на этом шаге; ручное заполнение карточек остаётся доступным.

## 5. Указать адрес и проверить подключение

1. Скопируйте Production URL Worker, например `https://fridge-photo-yourname.yoursubdomain.workers.dev`.
2. Откройте его в браузере. Наш код должен показать JSON с `"service":"fridge-photo"` и `"version":2`. Это подтверждает загрузку кода, но ещё не проверяет привязки и модель.
3. На каждом телефоне откройте **шестерёнку → Распознавание по фото**.
4. Вставьте URL в поле адреса, нажмите **Сохранить адрес распознавания**, затем **Проверить подключение**.
5. При успехе приложение покажет, что Worker и доступ семьи проверены, и оставшееся число попыток. Эта проверка обращается к D1, но фотографии не отправляет и модель не вызывает.

Адрес вводится без `/v1/...`, без токенов и параметров. На каждом телефоне он сохраняется отдельно. Используйте один Worker распознавания для общей семьи. Настройки ретранслятора обмена запасами менять не нужно.

## 6. Проверить настоящее распознавание

1. Откройте добавление продукта и сфотографируйте упаковку либо выберите фото.
2. При необходимости нажмите **«Снять срок крупно»** или **«Выбрать снимок срока»**. Второй снимок не заменяет основное фото карточки.
3. Нажмите **«Распознать через Cloudflare»**, проверьте выбранные кадры и подтвердите отправку.
4. На экране **«Проверьте маркировку»** сравните предложенные поля с упаковкой. Даты по умолчанию не выбраны. Дате без назначения вручную укажите «Годен до» или «Дата изготовления», только если назначение понятно из маркировки.
5. Нажмите **«Перенести в форму»**, при необходимости исправьте поля и затем **«Сохранить упаковку»**.
6. Проверьте появление карточки и основного фото на втором телефоне через уже работающий домашний Wi-Fi.

Сервис распознаёт напечатанные сведения, а не безопасность продукта по виду. Нечитаемый срок заполните вручную. Нетто на упаковке не означает фактический остаток: его можно исправить в форме. Автоматических повторов распознавания нет; отдельное нажатие и подтверждение создают новую попытку.

## Если не получилось

| Сообщение | Действие |
|---|---|
| Worker не разрешил доступ / HTTP 401 | Замените `ROOMS` значением из **настроек распознавания** этой семьи. Проверьте, что JSON вставлен целиком и оба телефона в одной семье |
| Неверный адрес или версия / HTTP 404, 405 | Укажите только Production URL. Полностью замените код Worker актуальным `worker.js` и нажмите Deploy |
| Worker не настроен / HTTP 503 | Проверьте привязки `AI`, `DB`, переменную `ROOMS` и числовой `DAILY_LIMIT` |
| Нет таблицы recognition_usage | Выполните SQL из шага 2 в той базе, которая выбрана в привязке `DB` |
| HTTP 429 | Достигнут суточный лимит. Подождите или заполните вручную |
| HTTP 502 | Проверьте доступность Workers AI, бесплатную квоту и настройку модели. Если ответ модели некорректен, снимите маркировку ближе и без бликов |
| Нет связи / тайм-аут | Проверьте открытие URL в браузере телефона. Доступность Cloudflare в РФ зависит от сети; сравните домашний Wi-Fi и мобильный интернет |
| Подключение проверено, распознавание не прошло | Подключение и запуск модели — разные проверки. Проверьте квоту Workers AI и попробуйте один чёткий снимок |

Не отключайте проверку TLS-сертификатов. При недоступном интернете распознавание не работает; список, ручное добавление и домашний обмен доступны.

## Приватность и проверка реализации

Фото передаётся по HTTPS, но модель Cloudflare видит изображение. Сам код Worker не хранит фото/текст в D1 и не пишет их в `console.log`; хранится только счётчик по UUID семьи/холодильника и дню. Не включайте запись тел запросов в журналы. Обработка и технические журналы провайдера определяются [правилами Workers AI](https://developers.cloudflare.com/workers-ai/platform/data-usage/).

В репозитории проверены клиентский контракт с подменой HTTP-соединения, обработка фото и подтверждение полей на Android, настоящий SQLite-счётчик и серверный контракт с подменой `AI.run`. Это не проверка фактического ответа облачной модели. Первое реальное распознавание выполняется после установки в вашем аккаунте, на шаге 6. Точность на разных упаковках ещё нужно оценить.

Отключение: очистите адрес распознавания на телефонах. Отзыв серверного доступа: удалите запись семьи из `ROOMS`. Ключ семьи, список и обмен по Wi-Fi от этого не меняются.

Тесты разработчика: Node.js 22.13+, без npm-зависимостей — `cd recognizer`, затем `npm test`. Один Worker может обслуживать несколько семей: в `ROOMS` добавляются дополнительные пары UUID и хеша. Адреса `/status` и `/recognize` требуют отдельный HMAC-токен `photo-v1`; ключ журнала запасов не передаётся.
